# 設計判断の記録

`docs/DESIGN.md` の未決事項や、実装時に決めたことを時系列で残す。設計書側を書き換えるときの元にする。

## M1

- 試作と設計が食い違う箇所（早すぎる入力の無視、未入力の締切に基本許容幅を使う、上位ノードの解放段階、球数追加でコアを消費）は試作準拠で移植した。`docs/PROTOTYPE_DIFF.md`
- セーブは `userData/sankyu/save/save.json`。userData は productName（三球）ではなく ASCII の `sankyu` に固定

## M2

### クラブ（回転数）

- 回転数 1〜3 は「別の難度曲線」として係数だけを変える。許容幅 ×1.0 / 0.8 / 0.62、キャッチ ×1.2 / 2.0 / 3.2、高度 ×1.0 / 1.35 / 1.7。拍と判定の仕組みは球と同じ
- 上の回転数は 1 つ下のクリーン 3 で解放。クリーンは回転数別に記録し、球数追加の条件には数えない
- 不採用: 回転数で滞空時間を伸ばし、入力を「受け」の瞬間に合わせる案。判定を 2 系統にするため

### 路上（拍手）

- 路上で投げるとキャッチの代わりに拍手。レート = 0.02 × (1 + 0.3 × 見せたパターン数) × 表現「変換」
- 20 拍続けるとそのパターンを「見せた」扱い。初回ボーナス 10（表現「見せ方」で +10/段階）
- 手動変換は 100 キャッチ単位、レート × 0.4
- 表現の系統（変換・見せ方）は路上が開くまで見えない
- 不採用: 見せたパターン数に応じて時間経過で拍手が貯まる放置型。路上で「投げる」意味が薄れるため

### パッシング

- 奇数拍は相方の投げ。入力不要で必ず成立、疲労は増えず、流れのボーナスも付かない
- 奇数のサイトスワップ値が相方へのパス（手 1 を相方として扱う）
- クリーンは `passClean` に別記録。球数追加の条件には数えない

### 舞台

- 解放は 7 球フラッシュ + 拍手 1000。ショー = 7 球のランで 40 拍を落とさずに投げ切ると完走
- ショー中は許容幅 ×0.8、高度 ×1.2。落としても拍手は減らず、やり直せる
- 球数追加は 7 球で止まり、「完走する」ボタンは無くした（試作の 4 球完走の代わり）

### 5〜7 球

- パターンは DESIGN の表どおり。4 球に 552 を足した。倍率と許容幅係数は 3・4 球の傾きで延長（未調整）
- 球数ごとの効果: 許容幅係数 1 / 1 / 0.95 / 0.9 / 0.85、クリーン間隔 30 / 30 / 27 / 24 / 20、高度 1 / 1 / 1.1 / 1.2 / 1.3
- 7 球フラッシュは「7 球すべてが同時に空中」を `run.ts` の投げごとに検出

### 封印（犠牲型コスト）

- クリーンを取ったパターンを封印すると、以後選べず記録も止まる。球数ごとに 1 つまで、7 球は不可
- 初期疲労を球数ごとに持たせた（3・4 球 0、5 球 0.1、6 球 0.2、7 球 0.3）。封印 1 つにつき、それより多い球数で −0.1
- 封印バランス（未決だった下げ幅）: 各球数で 1 つずつ封印すれば 7 球の初期疲労が 0 になる

### 体得点

- 球数を上げるごとに 1 点（合計 4 点）。体得ノードは系統ごとに 1 つ（5 つ）で、基本ノードが最大のとき 1 点で習得。4 点で 5 つのうち 4 つを選ぶ
- 効果: 型（許容幅 +20ms）、視野（追い目 +20%）、芯（初期疲労 −0.1）、無心（流れ ×2）、華（拍手レート ×1.5）

### 数値調整

- `tuning.ts` は開発モードで `userData/tuning.override.json` から上書きできる。`docs/TUNING.md`

## M3

- 拍の基準時刻は AudioContext.currentTime（ms 換算）。動かせない環境では performance.now() に落ちる。同じランの中で基準を混ぜない
- 入力オフセット補正は「クリックに合わせて 8 回叩く（最初の 2 拍は聞くだけ）→ 平均遅延」。入力時刻から引いて core に渡す
- 設定はセーブと別ファイル（settings.json）。言語切替は再読み込み（ラン中は不可）
- 最小化・非表示でランを一時停止し、復帰時に拍と滞空の時刻をずらす（shiftRun）
- ウィンドウを閉じる前に main が renderer にセーブを書かせる。応答が無くても 1.5 秒で閉じる

## M4

- steamworks.js は main プロセスの `electron/steam.ts` にだけ置く。require / init の失敗はすべて no-op
- 実績の対応表（core id → Steam API 名）は `electron/steam.ts`。App ID 480 のときは Spacewar の実績名に寄せる
- オーバーレイは `in-process-gpu` のみ（`disable-direct-composition` は付けない）。app ready より前にスイッチを足す
- 開発時は cwd に `steam_appid.txt` を書く。本番は `files` で除外し、steam.yml でも検査する
- 統計は total_catches / best_run / complete_ms。遊んだ時間は「拍数 × 間隔」で数える（state.playMs）
