# 画像差し替え計画

現状の絵はすべて Canvas のプリミティブ（円、角丸矩形、線）と CSS 変数の色で描いている。
アプリアイコンは Electron の既定のまま。Steam のストア素材は未着手。
この文書は「何を、どの順で、どの形式で差し替えるか」と、コード側の受け皿を決める。
凝った絵（多色・陰影・質感）に差し替えられることを前提にする。

## 方針

- **素材は 2 系統に分ける**
  - **ゲーム内の絵（球・クラブ・手・背景・相方・幕）はフルカラー**。色は素材が持つ。描画側では色を変えない
  - **UI アイコン（通貨・タブ・系統・鍵）は単色の SVG**。`currentColor` で CSS 変数の色を付け、テーマに追従させる
- **形式は絵柄で選ぶ**。ベクター調ならフルカラー SVG（拡大で崩れない、Canvas にそのまま描ける）。手描き・塗りの質感なら PNG か WebP を **2 倍解像度**で用意し、DPR 2 に合わせる。どちらでも読み込みと描画の経路は同じ
- **テーマ（ライト／ダーク）**は、色を後から付けるのではなく、絵そのものを両方の背景で成立するように作る。球・クラブ・手は陰影の付け方で 1 枚で足りる想定。背景だけはライト／ダークの 2 枚を持ってよい
- **描画の入口は `src/render/` に閉じる**。core と ui は画像を知らない
- **素材の不在で落ちない**。読み込み失敗時は今のプリミティブ描画にフォールバックする（Steam Deck や古い GPU での安全策、開発中の差し替え途中でも動く）
- **起動から練習場まで 3 秒以内**を守る。練習場に要る絵（球・手・拍の輪まわり）だけ起動時に読み、タブの絵（クラブ・路上・パッシング・舞台）はタブが開くときに遅延で読む

## コード側の受け皿

1. **`src/assets/`（新規）**: 素材の置き場。`game/`（フルカラー）と `ui/`（単色 SVG）に分ける。ファイル名は一覧の英名（`ball-coral.png` `club-sky.png` `hand-r.png` `floor-light.png` ...）
2. **`src/render/assets.ts`（新規）**: 素材の一覧と読み込み。Vite の `?url` で URL を持ち、`Image` にデコードして保持する
   - `load(group: 'arena' | 'club' | 'street' | 'passing' | 'stage'): Promise<void>` でグループ単位に遅延読み込み
   - `get(name): HTMLImageElement | null`。未読み込み・失敗は `null`（呼び出し側がフォールバック）
   - 失敗は `platform/log` に書く。1 枚の失敗で他を止めない
3. **`src/render/sprites.ts`（新規）**: `drawImage` の薄いヘルパ。中心座標・拡縮・回転・スプライトシートの切り出し（コマ番号）をまとめる。テーマは `document.documentElement` の `data-theme` と `prefers-color-scheme` から判定し、`-light` / `-dark` の付いた素材名を選ぶ
4. **`src/render/arena.ts`**: 球・クラブ・手・床・見せ場の光を `sprites` に置き換える。`get()` が `null` なら今の `arc` / `drawClub` / 線描画を使う
5. **UI アイコン**: `src/ui/icons.ts`（新規）に単色 SVG をインライン文字列で持ち、`currentColor` で CSS の色を受ける。DOM に直接埋め込む（画像リクエストを増やさない）
6. **`build/icon.png`**: 置くだけで electron-builder が拾う。`electron-builder.yml` に `icon` の指定は不要（既定パス）
7. **CSP**: `img-src 'self' data:` のままで良い。PNG / WebP / SVG はいずれも `'self'` で読める
8. **フォールバックの検証**: `tests/smoke.mjs` に「素材ディレクトリを空にして起動しても練習場が描ける」確認を足す

## 順番

1. **アプリアイコン**（今すぐ）。ビルド成果物の見た目に直結し、Steam の審査でも見る。1024×1024 の PNG を 1 枚作れば済む
2. **球・手・床**（M2 の間）。プレイ中に常に見える。`assets.ts` / `sprites.ts` とフォールバックをここで作る
3. **クラブ**（クラブタブの絵が固まったら）。回転の原点を素材で決める
4. **通貨・タブ・系統・鍵のアイコン**（M3 の設定画面と一緒に）。UI の情報量が増えるタイミング
5. **見せ場の光、路上の背景、相方、幕**（各タブの実装後）。ゲーム内容が固まってから
6. **Steam ストア素材**（M4 の最初）。スクリーンショットは 2〜5 が終わってから撮る。ストアページはリリース 2 週間前に公開する

## 決めること

- **絵柄**: ベクター調（SVG）か、手描き・塗り（PNG / WebP）か。これで形式と 2 倍解像度の要否が決まる
- **球の 4 色**: 素材側で固定する（この計画の前提）。ダークテーマでも同じ 4 色で成立するかを最初の 1 枚で確かめる
- **発注か自作か**: ゲーム内 20 点前後 + UI アイコン 17 点 + アプリアイコン 1 点 + ストア素材一式が目安。ライセンス表記は `docs/STEAM.md` のチェックリストに追加する
