# 画像差し替え計画

現状の絵はすべて Canvas のプリミティブ（円、角丸矩形、線）と CSS 変数の色で描いている。
アプリアイコンは Electron の既定のまま。Steam のストア素材は未着手。
この文書は「何を、どの順で、どの形式で差し替えるか」と、コード側の受け皿を決める。

## 方針

- **ベクター（SVG）を原本にし、PNG は生成物にする**。Canvas は DPR 1〜2 で描くので、球やクラブは SVG を `Image` として読み込んで `drawImage` するか、Path2D に変換して描く。拡大で崩れない
- **見た目はライト／ダークの 2 テーマに追従する**。色は CSS 変数（`--ivory` `--coral` `--sky` `--amber` `--ink`）から取る前提なので、素材は「形」だけを持ち、色は描画時に付ける（単色 SVG + `fill: currentColor`、または色差し替え用のマスク PNG）。テーマごとに 2 セット用意する案は却下
- **描画の入口は `src/render/` に閉じる**。core と ui は画像を知らない
- **素材の不在で落ちない**。読み込み失敗時は今のプリミティブ描画にフォールバックする（Steam Deck や古い GPU での安全策）

## コード側の受け皿

1. `src/render/assets.ts`（新規）: 素材の一覧と読み込み。`import ball from '../assets/ball.svg?url'` のように Vite 経由で URL を持ち、`Image` にデコードして保持する。`ready: Promise<void>` と `has(name): boolean` を持つ。読み込み失敗は `platform/log` に書いてフォールバック
2. `src/render/sprites.ts`（新規）: 「形の SVG に色を付けて描く」ヘルパ。`currentColor` を含む SVG 文字列を色ごとに `Image` 化してキャッシュする（色 × 形の組み合わせは十数個なので十分小さい）
3. `src/render/arena.ts`: 球・クラブ・手を `sprites` に置き換え。無ければ今の `arc` / `drawClub` を使う
4. `src/assets/`（新規）: SVG の置き場。ファイル名は素材一覧の英名（`ball.svg` `club.svg` `hand-r.svg` ...）
5. `build/icon.png`: 置くだけで electron-builder が拾う。`electron-builder.yml` に `icon` の指定は不要（既定パス）
6. CSP: `img-src 'self' data:` のままで良い。SVG を `data:` URL で `Image` にする場合もここで許可済み

## 順番

1. **アプリアイコン**（今すぐ）。ビルド成果物の見た目に直結し、Steam の審査でも見る。1024×1024 の PNG を 1 枚作れば済む
2. **球・クラブ・手**（M2 の間）。プレイ中に常に見える。テーマ追従の仕組み（`sprites.ts`）をここで作る
3. **通貨アイコンと鍵**（M3 の設定画面と一緒に）。UI の情報量が増えるタイミング
4. **背景（見せ場・路上・舞台）と相方**（各タブの実装後）。ゲーム内容が固まってから
5. **Steam ストア素材**（M4）。スクリーンショットは 2〜4 が終わってから撮る。ストアページはリリース 2 週間前に公開するので、M4 の最初に着手する

## 決めること

- キービジュアルの方向（線画か、塗りか）。ゲーム内の球は「輪郭 1.5px + 単色」なので、ストア素材もその延長が自然
- 球の色 4 つ（ivory / coral / sky / amber）を素材側で固定するか、CSS 変数のままにするか。ダークテーマで同じ 4 色が使えるなら固定して良い
- 発注するか自作するか。SVG 12 点 + アイコン 1 点 + ストア素材一式が目安。ライセンス表記は `docs/STEAM.md` のチェックリストに追加する
